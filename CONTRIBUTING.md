# Contributing

Contributions are welcome when they preserve product trust and reproducibility.

## Before opening a pull request

1. Use synthetic examples only; do not add personal data, private paths, secrets,
   official/controlled questions, or internal agent files.
2. Keep all AFOQT framing unofficial and avoid score, eligibility, or timing equivalence.
3. Add or update tests for changed content or behavior.
4. Run every command in the README quality-gate block.
5. Explain the user impact, technical decision, and verification evidence in the PR.

Question corrections should cite a public authoritative source when one exists.
Passing validation proves repository consistency, not official exam accuracy.
